# NEXIS — консультант ekt.kz

Прототип чат-ассистента для поиска электротехнических товаров, проверки остатков, подбора подтверждённых аналогов и предварительного разбора спецификаций. Проект подготовлен для кейса №1 HackAlem AI 2026.

## Возможности

- Поиск в каталоге ekt.kz по артикулу и названию с Basic Auth.
- Карточка товара с ценой, остатками по складам, свойствами и ссылками, если они есть в API.
- Подбор аналогов только при подтверждённом положительном остатке и совпадающих параметрах.
- Ответы по условиям покупки из локальной базы знаний.
- Добавление в демонстрационную корзину после явного действия пользователя, с повторной проверкой цены и остатка на сервере.
- Предварительная смета по PDF, TXT, DOCX, XLSX и XLS. OCR изображений требует установленного Tesseract с языками `rus` и `eng`.
- Русскоязычный frontend-виджет; при недоступности backend интерфейс может использовать явно помеченные демо-данные.

## Запуск

Требуются Python 3.11+ и Node.js.

1. Скопируйте `.env.example` в `.env` в корне проекта и заполните `EKT_API_USER` и `EKT_API_PASS`. Учётные данные не добавляйте в Git. `OPENAI_API_KEY` необязателен: без него backend использует правило-ориентированный режим и всё равно обращается к каталогу ekt.kz.
2. Установите зависимости backend и запустите API:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

Swagger UI: `http://localhost:8000/docs`.

3. В другом терминале запустите frontend:

```powershell
cd frontend
npm install
npm run dev
```

Vite: `http://localhost:5173`. Для другого backend задайте `VITE_API_BASE_URL`, например `http://localhost:8000/api`.

## Основные endpoint’ы

- `GET /api/health` — состояние сервиса.
- `GET /api/products?page=1&limit=20` — загруженные страницы каталога.
- `POST /api/agent/chat` — сообщение, история и reasoning steps.
- `POST /api/agent/upload-spec` — multipart загрузка спецификации (до 15 МБ).
- `GET /api/cart?session_id=...` — демонстрационная корзина.
- `POST /api/cart/offer?session_id=...` — проверка выбранного товара и количества, выдача одноразового подтверждения.
- `POST /api/cart/add?session_id=...` — добавление после подтверждения с `product_id`, `quantity`, `confirmed: true` и `offer_token`; цена и остаток повторно проверяются на backend.
- `GET /api/faq` — категории и статьи базы знаний.

Полные схемы запросов и ответов — в [`docs/api-contract.md`](docs/api-contract.md). Информация по кейсу и критерии приёмки — в [`docs/task-spec.md`](docs/task-spec.md).

## Важные ограничения прототипа

- Демонстрационная корзина хранится в памяти backend и не переносится в аккаунт ekt.kz. Ссылка на сайт открывает его корзину, но сама по себе не передаёт туда позиции прототипа.
- При сбое ekt.kz API backend не подставляет придуманные остатки. Он сообщает, что наличие не удалось проверить.
- В предоставленной карточке товара `515291` в названии указано 160 А, а в свойстве `NOMINALNYY_TOK` — 250 А. Backend помечает такое расхождение; подбирать аналог автоматически по конфликтующей характеристике нельзя.
- Для JPEG/PNG/WEBP нужен установленный Tesseract OCR. Если OCR недоступен, загрузка вернёт понятную ошибку.
- Интеграция с CRM и фактическое создание заявки менеджеру пока не подключены.

## Структура

- `backend/main.py` — FastAPI маршруты и серверная валидация корзины и загрузок.
- `backend/agent_service.py` — агент, tool calling, офлайн-ответы и шаги reasoning.
- `backend/ekt_client.py` — Basic Auth клиент, пагинация, поиск, карточка товара и аналоги.
- `backend/knowledge_base.py` — локальная база справочных статей.
- `backend/spec_parser.py` — извлечение строк из файлов и сопоставление с каталогом.
- `frontend/` — интерфейс виджета.
- `docs/api-contract.md` — единый API-контракт.
- `docs/improvement-plan.md` — приоритеты дальнейшей работы по ТЗ.
