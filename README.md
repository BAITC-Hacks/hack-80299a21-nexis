# NEXIS / ChipAI — ИИ-консультант для ekt.kz

**HackAlem AI 2026 · команда NEXIS · кейс №1 ТОО «Электрокомплект»**

Чат для подбора электротехнической продукции: от вопроса о товаре или загруженной спецификации до списка закупки, подтверждённого покупателем.

[Репозиторий](https://github.com/BAITC-Hacks/hack-80299a21-nexis) · [Архитектура](docs/architecture.md) · [API-контракт](docs/api-contract.md) · [Аудит и результаты проверок](docs/frontend-backend-audit.md)

## 1. Какую проблему решает проект

Частному покупателю или закупщику компании нужны характеристики, сертификаты, остатки по складам, аналоги и условия покупки. Обычно эти вопросы требуют обращения к менеджеру и замедляют выбор товара.

ChipAI объединяет консультацию и подготовку списка закупки в одном окне. Покупатель получает данные каталога и объяснение рекомендаций, а менеджер может сосредоточиться на сложных запросах. Снижение времени консультации и нагрузки на менеджеров — цель проекта; эти бизнес-показатели пока не измерялись.

**Текущий результат:** работающий frontend и backend с живым каталогом ekt.kz, обработкой документов и сохраняемой демонстрационной корзиной. Передача заказа в реальную корзину ekt.kz требует отдельного API партнёра.

## 2. Что реализовано

| Возможность | Что получает пользователь |
| --- | --- |
| Поиск товара | Поиск по ID, артикулу, названию и электрическим параметрам; нормализация обозначений вроде 3х2,5 / 3×2.5 |
| Карточка товара | Цена, артикул, характеристики, остатки по складам, время проверки, ссылка на товар и сертификат, если он есть в API |
| Контроль качества данных | Неизвестные значения остаются неизвестными; противоречия характеристик показываются предупреждением |
| Аналоги | Подбор по известным техническим параметрам, проверка наличия и краткое объяснение совпадений |
| Условия покупки | Ответы об оплате, доставке и минимальной партии со ссылками на источники |
| Продолжение диалога | Уточнения «нужно пять», «а в Алматы?», «подешевле»; контекст товара, количества, города и бюджета |
| Спецификации и изображения | PDF, TXT, DOCX, XLSX, XLS, JPEG, PNG, WEBP; найденные и неизвестные строки, количество и полная либо частичная смета |
| Подтверждаемая корзина | Добавление, изменение количества и удаление только после отдельного согласия; проверка цены, остатка и кратности |
| Сохранение результата | Корзина в SQLite, ссылка на её актуальное состояние; CSV-экспорт через API |
| Интерфейс | Чат, карточки, статусы выполненных действий, выбор количества, маскот ChipAI и панель корзины |
| Языки | Русские и базовые казахские ответы; английский интерфейс с явным пояснением, что консультация идёт на русском |

Быстрые вопросы отправляются в backend. Ошибки API не подменяются синтетическими ответами. Фоновая витрина интерфейса иллюстративная и подписана; её цены и товары не используются в консультации.

## 3. Как работает решение

1. Пользователь открывает чат и вводит вопрос, артикул или прикрепляет спецификацию.
2. Frontend получает анонимную серверную сессию и отправляет запрос в FastAPI.
3. Агент определяет сценарий: поиск, уточнение параметров, наличие в городе, аналог или условия покупки. Файлы проходят серверный разбор.
4. Backend запрашивает каталог и возвращает ответ, структурированные карточки, источники и статусы выполненных действий.
5. Для выбранного товара и количества сервер создаёт предложение. Пользователь видит название, цену, количество и предупреждения.
6. Только после явного подтверждения сервер повторно проверяет данные и меняет корзину. Токен предложения одноразовый и связан с сессией, товаром, количеством и ценой.
7. Пользователь открывает актуальную сохранённую корзину по ссылке.

Загрузка файла и просмотр товара сами по себе не меняют корзину. Если часть строк не распознана, смета явно обозначается как неполная. Превышение остатка, повторное подтверждение или изменившаяся цена отклоняются.

| Компонент | Технологии |
| --- | --- |
| Backend | Python, FastAPI, Uvicorn, Pydantic |
| Frontend | TypeScript, Vite 8, HTML/CSS, Tailwind CSS 4; React 19 используется для маскота ChipAI |

| Каталог | HTTPS API ekt.kz с Basic Auth, клиент на Requests, кеш с TTL |

| Проверки | Python unittest, FastAPI TestClient, Node.js test runner, TypeScript typecheck |

### Как устроен агент

В проекте один AgentService. Он сочетает программные правила, поиск по данным и необязательное планирование инструментов моделью.

Модели доступны **пять инструментов чтения**: search_products, get_product_detail, find_analogs, query_knowledge_base и check_city_stock. Фактический ответ о товаре собирается сервером из полученных данных. Изменение корзины выполняется отдельным сервисом после проверки согласия.

Поиск использует точные идентификаторы, лексическое ранжирование и фильтры электрических параметров. База условий покупки — небольшой версионированный корпус из шести статей с поиском по ключевым словам и ссылками на источники. Векторная база и embeddings не используются.

**Без OPENAI_API_KEY** работают программные правила и тот же живой каталог. При настроенном ключе подключается модель; OPENAI_MODEL позволяет изменить её имя. В последней проверенной конфигурации ключ отсутствовал, поэтому настоящие ответы OpenAI не проверялись. Статусы reasoning_steps показывают действия инструментов, а не внутренние рассуждения модели.

## 5. Архитектура проекта

~~~mermaid
flowchart TD
    UI["Браузер: чат и корзина"] -->|"HTTP /api, через nginx в Docker"| API["FastAPI"]
    API --> Agent["AgentService: сценарии и контекст"]
    Agent --> Catalog["EktClient: поиск и кеш"]
    Catalog -->|"HTTPS GET + Basic Auth"| EKT["Каталог ekt.kz"]

    Agent -->|"Необязательный Function Calling"| LLM["OpenAI API"]
~~~

| Файл или каталог | Назначение |
| --- | --- |

| backend/main.py | HTTP API, валидация, CORS, лимиты и обработка ошибок |
| backend/agent_service.py | Сценарии консультации и вызов инструментов |
| backend/dialogue_context.py | Краткий контекст выбора в рамках сессии |
| backend/ekt_client.py | Данные ekt.kz, кеш, поиск и аналоги |
| backend/cart_service.py | SQLite, предложения, подтверждения и ссылки корзины |
| backend/spec_parser.py | Извлечение текста, OCR и сопоставление строк |

API v2.1 включает /api/session, /api/agent/chat, /api/agent/upload-spec, /api/cart/offer, /api/cart/add, /api/cart/change-offer, /api/cart/change и /api/cart. Схемы, ошибки и остальные маршруты описаны в [контракте](docs/api-contract.md) и Swagger.

## 6. Установка и запуск

### Вариант A — Docker, включая OCR

Нужны Git, Docker с Compose и доступ в интернет. На Windows используется Docker Desktop в режиме Linux containers. Все дальнейшие команды выполняются из корня проекта.

**1. Получите код:**

~~~sh
git clone https://github.com/BAITC-Hacks/hack-80299a21-nexis.git
cd hack-80299a21-nexis
~~~

**2. Создайте .env из шаблона, сохранив уже настроенный файл.**

PowerShell:

~~~powershell
if (!(Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
~~~

Linux/macOS:

~~~sh
test -f .env || cp .env.example .env
~~~

**3. Заполните настройки в .env:**

| Переменная | Значение |
| --- | --- |
| EKT_API_BASE | https://ekt.kz/api — уже указано в шаблоне |
| EKT_API_USER, EKT_API_PASS | Учётные данные API, предоставленные организаторами или партнёром; обязательны для живого каталога |
| OPENAI_API_KEY | Необязательно: оставьте пустым для запуска по правилам |
| OPENAI_MODEL | gpt-4o-mini по умолчанию; используется при включённой модели |
| EKT_CATALOG_PAGES | 4 по умолчанию; число страниц каталога для поиска |
| NEXIS_PUBLIC_URL | Необязательно для Docker: публичный адрес frontend при размещении; локально используется http://localhost:5173 |

Секреты остаются в .env на backend. Этот файл исключён из Git; во frontend их передавать не нужно. Полный список настроек находится в [.env.example](.env.example).

**4. Соберите и запустите приложение:**

~~~sh
docker compose up --build -d
docker compose ps
~~~

| Адрес | Назначение |
| --- | --- |
| [http://localhost:5173](http://localhost:5173) | Приложение с чатом |
| [http://localhost:8000/docs](http://localhost:8000/docs) | Swagger API |
| [http://localhost:5173/api/health](http://localhost:5173/api/health) | Состояние сервиса и конфигурация возможностей |

Первый запуск загружает образы и зависимости. Backend должен перейти в состояние healthy. Health показывает конфигурацию; успешный доступ к каталогу проверяется запросом товара.

**5. Логи и остановка:**

~~~sh
docker compose logs --tail=100 backend frontend
docker compose down
~~~

Обычная остановка сохраняет SQLite в именованном Docker volume. Порты 5173 и 8000 должны быть свободны. Если каталог недоступен, проверьте настройки API и сообщение об ошибке в чате. Подробнее: [Docker и OCR](docs/docker-setup.md).

### Вариант B — локальная разработка без Docker

Проверенное окружение: Windows, Python 3.14 и Node.js 24 с npm. Получите репозиторий и заполните .env по шагам выше.

Первый запуск устанавливает зависимости и запускает оба сервера:

~~~powershell
python backend/scripts/dev.py --install
~~~

Повторный запуск:

~~~powershell
python backend/scripts/dev.py
~~~

Приложение доступно на localhost:5173, API — на localhost:8000. Для других портов:

~~~powershell
python backend/scripts/dev.py --api-port 8002 --ui-port 5174
~~~

Launcher согласует API-адрес и CORS; остановка — Ctrl+C. Для фото и сканов в нативном режиме отдельно установите Tesseract с языками rus/eng/kaz и при необходимости задайте TESSERACT_CMD. Текстовые PDF, Word, Excel и TXT не требуют OCR.

## 7. Как проверить решение жюри

### Сценарий на 5–7 минут

Начните с пустой демонстрационной корзины. Каталог живой: цены и остатки могут измениться, поэтому сравнивайте ответ с текущей карточкой, а не с фиксированными числами в примере.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Откройте приложение → ChipAI → быстрый вопрос «Товар 515291» | Реальная карточка, характеристики и остатки. Если сохраняется расхождение тока 160/250 А в API, оно показано предупреждением |
| 2 | Напишите «А в Алматы?» | Ответ про склады города для выбранного товара; корзина не меняется |
| 3 | Нажмите «Проверить и добавить» у доступного товара | Отдельное окно с товаром, количеством, свежей ценой и предупреждениями |
| 4 | Нажмите «Отмена» | Корзина остаётся пустой |
| 5 | Повторите выбор и нажмите «Да, подтверждаю» | Товар появляется в серверной корзине; количество не превышает остаток |
| 6 | Откройте корзину, измените количество и подтвердите действие | Новое количество записывается после согласия; ссылка открывает актуальное состояние |
| 7 | Перезагрузите страницу | Корзина восстанавливается из серверного хранилища |
| 8 | Загрузите docs/sample_specification.pdf или docs/sample_specification.txt | Артикул 200300285_ найден с количеством 2; неизвестная строка показана отдельно; смета неполная, корзина не меняется |
| 9 | Спросите «Какие условия оплаты и доставки?» | Содержательный ответ со ссылками на источники |
| 10 | Переключите язык на KZ и повторите вопрос об условиях | Казахский ответ без ошибки несовместимого кода языка |

Если товар 515291 недоступен, выберите другую доступную карточку для шагов с корзиной. Конфликт характеристик требует уточнения у менеджера; этот сценарий проверяет локальную демо-корзину и не оформляет покупку.

**Текстовое подтверждение.** Откройте приложение в приватном окне браузера с новой сессией. До выбора города отправьте «Артикул 030300435_, нужно 2 шт». Этот артикул использовался в браузерной приёмке. Если текущий остаток достаточен и нет предупреждений, агент предложит добавление. Ответьте «Да, добавь»: добавятся 2 штуки. Повторное «Да, добавь» без нового предложения не должно добавить их ещё раз. При изменении данных каталога используйте другой доступный товар без противоречий.

**Отсутствующий товар и аналоги.** Запросите позицию с нулевым текущим остатком. Агент проверяет технически подходящие альтернативы и объясняет совпадения. Если в доступной выборке подходящих вариантов нет, он сообщает об этом.

## 8. Данные и интеграции

- **Каталог партнёра:** HTTPS GET https://ekt.kz/api/products, пагинация ?page=2 и карточка https://ekt.kz/api/products/detail?id=515291. Авторизация Basic Auth выполняется только backend.
- **Данные товара:** ID, артикул, название, цена, количество, склады, свойства, изображения, ссылки и документы, если они присутствуют в ответе API.
- **Свежесть:** страницы кешируются на 300 секунд, детали — на 30 секунд по умолчанию. Перед добавлением или изменением положительного количества цена и остаток проверяются заново.
- **Условия покупки:** локальная база со ссылками на официальные страницы ekt.kz и датами проверки. Это подготовленный корпус, а не автоматический обход сайта при каждом вопросе.
- **OpenAI:** необязательная внешняя интеграция для выбора инструментов. При её включении ограниченная история и результаты инструментов передаются модели; загруженные документы ей не отправляются.
- **Хранение:** SQLite сохраняет корзины и служебные данные сессий. Краткий контекст выбора хранится в памяти до 30 минут, максимум для 1024 сессий; после перезапуска теряется.
- **Демонстрационные данные:** синтетический транспорт используется в автотестах. Примеры PDF/TXT содержат один реальный артикул и одну намеренно неизвестную строку. Приложение не сохраняет загруженные файлы; временный multipart-файл закрывается после обработки.

Решение не запрашивает платёжные реквизиты. История чата не сохраняется в БД. Ссылки корзины имеют временный токен чтения.

## 9. Ограничения текущей версии

1. **Корзина демонстрационная.** API партнёра предоставляет только чтение каталога. Товар не резервируется, заказ и оплата на ekt.kz не создаются. Нужны официальный API корзины и привязка к покупателю.
2. **Каталог покрыт частично.** По умолчанию поиск работает по первым четырём страницам; настройка допускает до 50. Прямой запрос ID доступен за пределами выборки. Полного индекса магазина нет.
3. **Аналоги зависят от качества данных.** Проверяются поддерживаемые семейства и известные параметры. Нельзя гарантировать подходящий аналог при неполных характеристиках или вне выборки.
4. **OCR распознаёт читаемую маркировку.** Определение точной модели по внешнему виду без текста не реализовано. Двоичный Word .doc нужно преобразовать в .docx.
5. **Есть ограничения файлов:** до 15 МиБ на файл, до 250 товарных строк; дополнительные ограничения страниц, архивов и изображений описаны в API-контракте.
6. **Количество целочисленное.** Дробный метраж кабеля требует расширения контракта единиц измерения.
7. **Языковая поддержка ограничена.** Казахские ответы используют базовые шаблоны; не все названия характеристик и ошибки переведены. EN — язык интерфейса, ответы пока на русском.
8. **Нет CRM и авторизации покупателя сайта.** Вместо фиктивной заявки возвращаются официальные контакты. Есть анонимные сессии, но нет истории для авторизованных покупателей.
9. **Прототип ещё требует эксплуатационной проверки.** Реальная модель OpenAI, нагрузка и SLA не проверены. Контекст, кеш и лимитер локальны процессу; несколько воркеров требуют общего состояния. Потоковой выдачи ответа нет.
10. **Проверка устройств неполная.** Адаптивная вёрстка сохранена и desktop осмотрен; отдельная приёмка на настоящем телефоне остаётся в плане.

Следующие улучшения и внешние зависимости перечислены в [обновлённом плане](docs/integration-plan.md).

## 10. Deployed-версия и полезные ссылки

**Публичная deployed-ссылка для текущей версии в репозитории не указана.** Проверенная версия запускается локально: [http://localhost:5173](http://localhost:5173). Этот адрес доступен на компьютере, где запущен проект.

Для публичного размещения понадобятся HTTPS, публичный домен, настройки NEXIS_PUBLIC_URL/CORS и постоянное хранилище. Локальный Compose публикует порты только на 127.0.0.1; размещение на самом ekt.kz пока не выполнено.
