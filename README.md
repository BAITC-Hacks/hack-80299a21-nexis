# NEXIS — консультант ekt.kz

Backend прототипа для кейса №1 HackAlem AI 2026. Поиск товаров, проверка характеристик и остатков, аналоги, условия покупки, разбор спецификаций и корзина с явным подтверждением.

## Быстрый запуск backend

Python 3.11+; проверено на Python 3.14 / Windows. Из корня репозитория:

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-lock.txt
Copy-Item .env.example .env
# Заполните EKT_API_USER и EKT_API_PASS в .env.
.\.venv\Scripts\python.exe backend/main.py
~~~

Если .env уже настроен, сохраните его. Swagger: http://localhost:8000/docs.
OPENAI_API_KEY необязателен: без него работает поиск и консультация по правилам с теми же данными ekt.kz. При наличии ключа доступны read-only Function Calling инструменты. Текст ответа формируется из полученных фактов.

Для разработки зависимости перечислены в backend/requirements.txt; requirements-lock.txt фиксирует проверенное окружение. На другой ОС могут потребоваться соответствующие системные библиотеки.

## Что реализовано

- Basic Auth клиент каталога: пагинация, поиск по ID/артикулу/названию, TTL кеша, время проверки, склады и сертификаты из карточки.
- Проверка аналогов по параметрам, единицам измерения и подтверждённому наличию. Неоднозначные характеристики блокируют автоматическую рекомендацию.
- База условий покупки со ссылками и датами проверки; ответы на русском и базовые шаблоны на казахском.
- SQLite корзина и анонимные сессии. Одноразовое подтверждение связано с сессией, товаром, количеством и ценой; при добавлении API повторно проверяет остаток и цену.
- Реальная страница просмотра сохранённой демонстрационной корзины и CSV список для закупки.
- PDF, TXT, DOCX, XLSX, XLS и OCR маркировки на изображениях; найденные и нераспознанные строки, количество, частичная смета.
- Ограничения запросов/загрузок, проверка файлов, изоляция сессий, согласованные ошибки, action steps и структурированные карточки.

## Проверка

~~~powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -p "test_*.py" -v
.\.venv\Scripts\python.exe backend/scripts/smoke_live.py
~~~

Тесты используют синтетический транспорт и временную SQLite. smoke_live.py читает живой API с учётными данными из .env; добавляет позицию только в изолированную временную демо-корзину. Записи на стороне ekt.kz не выполняются.

## Границы прототипа

- От партнёра получены только GET API каталога. Демонстрационная корзина переживает перезапуск, но не резервирует товар и не передаёт позиции в реальную корзину ekt.kz. Для оформления нужен официальный механизм партнёра.
- Поиск использует репрезентативную выборку: по умолчанию первые 4 страницы, до 50 через настройку. Прямой запрос числового ID получает карточку за пределами выборки. Полный каталог не индексируется.
- Фото и сканы требуют установленного Tesseract и языковых данных. Без OCR возвращается понятная ошибка. По фотографии без читаемой маркировки товар не угадывается. Старый Word .doc нужно преобразовать в .docx.
- Количество сейчас целочисленное. Отрез кабеля с дробным метражом требует отдельного контракта единиц измерения.
- Ответ зависит от скорости партнёрского API/модели. Есть таймауты и кеш, но SLA «несколько секунд» под нагрузкой ещё не измерен.
- В frontend в рамках этой backend-доработки изменений нет. Подключение UI к новым сессиям, подтверждениям и загрузкам описано в [руководстве интеграции](docs/ekt-integration-guide.md).
- CRM не подключена: возвращается официальная страница контактов без фиктивного номера заявки.

## Структура

| Путь | Назначение |
| --- | --- |
| backend/main.py | API, CORS, валидация, ограничения запросов и загрузок |
| backend/agent_service.py | Чат, read-only инструменты, ответы из фактов |
| backend/cart_service.py | SQLite сессии, предложения, подтверждение и ссылки корзины |
| backend/ekt_client.py | Каталог, свежесть, характеристики и аналоги |
| backend/spec_parser.py | Документы, OCR и сопоставление спецификации |
| backend/knowledge_base.py | Условия покупки и источники |
| backend/tests/ | Приёмочные и защитные сценарии |
| frontend/ | Отдельный интерфейс; запуск описан в его README |
| docs/ | ТЗ, архитектура, API и план |
