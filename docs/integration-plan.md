## Критерий завершения текущей интеграции

- Свежая копия репозитория запускается по инструкции с собственным .env.
- Поиск и быстрые вопросы используют настоящий API; ошибки не подменяются демонстрационными товарами.
- Выбор → предложение → подтверждение → добавление/изменение/удаление → актуальная корзина работают согласованно.
- Без согласия сервер не меняет корзину; старая цена, токен или количество не разрешают запись.
- Загрузка передаёт файл на сервер и показывает найденные, неоднозначные и неполные позиции.
- Desktop/mobile остаются пригодными для поиска, чтения ответа и подтверждения.

4. Собрать реальные спецификации и фотографии для оценки распознавания, уточнений и совпадений.
5. Согласовать дробные количества/единицы измерения и расширить контракт.
6. Измерить задержки и нагрузку; определить общее хранение контекста/кеша/лимитов для нескольких процессов.

## Зависимости от партнёра и окружения

| Зависимость | Сейчас | Что требуется |
| --- | --- | --- |
| Реальная корзина ekt.kz | Только GET каталога; локальный список закупки | Авторизованный API корзины, связь с покупателем, резерв/идемпотентность и URL оформления |
| CRM | Возвращаются официальные контакты | Документация и тестовый доступ для реальной передачи заявки |
| OpenAI | Ключ в проверенном окружении отсутствует | Действующий ключ и оценка результатов/задержек |
| OCR | Работает в Docker; native Windows отдельно | Для сложных фото — читаемая маркировка и оценка качества |
| Полный каталог | 4 страницы по умолчанию, максимум 50; прямой ID | Выгрузка, поиск партнёра или полный индекс |
| Размещение на ekt.kz | Локальная интеграция | Способ встраивания, HTTPS, домен, CORS и эксплуатационные требования |

Цена, наличие, официальные сертификаты, оформленный заказ и отправленная заявка не имитируются. [Подробный аудит](frontend-backend-audit.md) и [контракт v2.1](api-contract.md) фиксируют фактическое поведение.
