# Архитектура NEXIS / ChipAI

API v2.1, 23 сентября 2026. Один агент-консультант, серверный сервис корзины и адаптивный frontend.

~~~mermaid
flowchart TD
    UI[ChipAI: TypeScript, карточки, корзина, файлы] --> Proxy[nginx в Docker / прямой API в dev]
    Proxy --> API[FastAPI: валидация, CORS, лимиты]
    API --> Agent[AgentService]
    Agent --> Context[Контекст выбора в RAM]
    Agent --> Tools[Пять инструментов чтения]
    Tools --> Catalog[EktClient: поиск, карточки, аналоги]
    Agent --> KB[Условия покупки с источниками]
    Catalog --> EKT[GET API ekt.kz]
    API --> Parser[Документы и локальный Tesseract]
    Parser --> Catalog
    Agent --> Cart[CartService: предложение и подтверждение]
    API --> Cart
    Cart --> Catalog
    Cart --> DB[(SQLite)]
    API --> View[Страница текущей демо-корзины]
    View --> DB
~~~

## Компоненты

| Компонент | Назначение |
| --- | --- |
| frontend/src/main.ts | Чат, карточки, реальные загрузки, диалог подтверждения, панель корзины |
| frontend/src/chat/api.ts | Сессия, X-Session-Id, таймауты, ошибки, восстановление истёкшей сессии |
| frontend/src/chat/products.ts | Проверяемая нормализация цены, остатков, свойств, документов и предупреждений |
| frontend/src/components/ChipMascot.tsx | Маскот на React с состояниями ожидания и результата |
| backend/main.py | API, строгие request-модели, ограничения, HTML/CSV корзины |
| backend/agent_service.py | Консультация по правилам и необязательный цикл вызова инструментов моделью |
| backend/dialogue_context.py | Временный контекст выбранного товара, количества, города, бюджета и категории |
| backend/ekt_client.py | Basic Auth, кеш, поиск, нормализация электрических параметров и аналоги |
| backend/cart_service.py | Все операции корзины, предложения, подтверждение, SQLite и ссылки чтения |
| backend/spec_parser.py | Извлечение документов, OCR, сопоставление строк и смета |
| backend/knowledge_base.py | Небольшая справочная база с retrieval по темам, ссылками и датами проверки |

Векторной БД нет. Поиск использует артикулы, нормализованные слова/обозначения и известные параметры. Каталог ограничен выбранными страницами.

## Агент и контекст

Модель при наличии OPENAI_API_KEY может выбирать search_products, get_product_detail, find_analogs, query_knowledge_base и check_city_stock. Результаты передаются в следующий шаг цикла. Цикл ограничен тремя итерациями и шестью инструментами. Программные правила обеспечивают консультацию при отсутствии/ошибке модели; цена и наличие всегда берутся из каталога.

Приветствия и широкие запросы получают ответ или уточнение. Ссылки «этот товар», вопросы о другом городе, количестве и более низкой цене используют контекст выбора. Более дешёвый вариант должен иметь подтверждённые подходящие параметры, меньшую цену и доступность с учётом запрошенного города.

Контекст в RAM ограничен 30 минутами с последнего обновления и 1024 сессиями. Ключ — хеш сессии; сохраняются только product_id, quantity, city, budget и family. После перезапуска он исчезает. Контекст не является согласием на запись и не заменяет предложение корзины.

reasoning_steps — события выполненных действий, возвращаемые вместе с итоговым JSON. UI во время ожидания показывает обработку, затем журнал результата. SSE и потоковая передача шагов не реализованы.

## Корзина

1. /api/session создаёт случайный идентификатор гостевой корзины.
2. /cart/offer или /cart/change-offer формирует серверное предложение.
3. UI показывает товар, артикул, цену, количество, предупреждения и отдельную кнопку подтверждения.
4. /cart/add или /cart/change принимает одноразовый токен, связанный с сессией, товаром, количеством, ценой и видом операции.
5. Положительное количество требует повторной проверки каталога. BEGIN IMMEDIATE защищает проверку и запись от повторов и одновременного изменения.
6. Ответ возвращает актуальные позиции и ссылку с отдельным токеном чтения.

При добавлении quantity — приращение. При изменении quantity — итоговое количество, ноль означает удаление. Для изменения проверяется previous_quantity; старое предложение не перезаписывает новую корзину. Удаление остаётся доступным при сбое каталога и требует подтверждения.

Текстовое подтверждение добавления относится только к действующему предложению чата. Отрицание, цитата, вопрос или история не меняют корзину. Модель не имеет инструмента записи.

SQLite переживает перезапуск. Цена сохранённой позиции соответствует последней подтверждённой операции; резервирования на стороне партнёра нет. Просмотр ссылки и открытие панели не оформляют заказ и не очищают позиции.

## Frontend и достоверность

Сервер — источник состояния корзины. localStorage хранит идентификатор гостевой сессии и предпочтение языка; старые локальные демо-корзины не подставляются. При 401 UI обновляет сессию, но не повторяет POST автоматически. После неопределённого результата записи UI перечитывает корзину.

Цена/остаток с null или verified:false показываются как неизвестные; добавление блокируется. Свойства отображаются как name:value, сертификаты — только по полученным ссылкам. Карточки показывают склады, время и предупреждения. Ошибки API не заменяются синтетическими ответами; быстрые вопросы вызывают настоящий чат.

RU отправляет ru, KZ — kk. EN меняет интерфейс и использует ru для консультации с явным пояснением. Полной английской консультации пока нет.

## Документы

Frontend отправляет содержимое файла multipart-полем file. Backend ограничивает размер, количество строк/страниц/символов, проверяет сигнатуры и извлекает текст. PDF-сканы и изображения обрабатываются локальным Tesseract.

Сопоставление возвращает найденные и неоднозначные строки, запрошенное количество, проверенные цену/остаток и известную часть суммы. Неизвестное количество не заменяется единицей. Загрузка не меняет корзину и не передаёт документ модели.

## Развёртывание и границы

Docker Compose: nginx frontend на localhost:5173, backend на localhost:8000, SQLite в именованном volume. nginx передаёт /api и /cart на backend; URL корзины использует публичный адрес frontend. Нативный dev.py запускает Vite и FastAPI и согласует порты/CORS.

Кеш, контекст и лимитер локальны одному процессу. Для нескольких воркеров нужны общее состояние, лимиты и нагрузочная проверка. Требуются HTTPS и настройки публичного адреса при развёртывании.

Партнёр предоставил только GET API. Настоящая корзина ekt.kz, резерв, оплата и CRM не подключены. Ограничены категории аналогов, объём каталога, целочисленное количество и качество OCR. Проверка модели с реальным ключом и браузерная приёмка отслеживаются в [плане](integration-plan.md).
