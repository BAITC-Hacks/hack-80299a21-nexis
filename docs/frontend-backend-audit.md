# Проверка совместимости backend и frontend

Дата: 23 сентября 2026. Backend: 8c99716. Проверены frontend из main (ca7299a) и новая удалённая frontend-ui-dev (b499414).

По решению пользователя в main отправляется только backend. Frontend не редактировался и не объединялся. Его отдельные незакоммиченные изменения в другом worktree сохранены.

## Выполненные проверки

- Backend: 47 тестов прошли; синтетический транспорт, временная SQLite, сетевые обращения не требуются.
- Frontend main: npm ci и npm run build прошли во временной копии.
- Frontend b499414: npm ci, npm run build и npm run typecheck прошли во временной копии.
- Запросы по текущему frontend-контракту воспроизведены через FastAPI TestClient: добавление получает 422; language=ru → 200, kz/en → 422; legacy UUID-сессия → 200.
- Сквозной браузерный сценарий не выполнялся. Сборка подтверждает компиляцию, но обнаруженные несовместимости API сохраняются.

## Расхождения, требующие исправления frontend

### 1. P1 — добавление кнопкой несовместимо с защищённым API

В обеих версиях frontend отправляет /cart/add с product_id, article, name, price, quantity, image. Backend принимает product_id, quantity, confirmed и offer_token; лишние поля запрещены.

Фактический результат: HTTP 422 по article/name/price/image. После удаления лишних полей всё равно потребуется действительное явное подтверждение. Без него сервер правильно откажет в записи.

Исправление: /cart/offer → показать серверное предложение → явное подтверждение → /cart/add с одноразовым токеном. Отображать data_quality_warnings и не подставлять цену из браузера. При 409 — новое предложение и новое подтверждение.

Места: main frontend/src/main.js:507; [новая ветка: addToCart](https://github.com/BAITC-Hacks/hack-80299a21-nexis/blob/b499414/frontend/src/main.js#L869).

### 2. P1 — загрузка файлов не вызывает серверный парсер

Обе версии при files.length возвращают статическое сообщение; POST /agent/upload-spec отсутствует. Backend endpoint уже поддерживает multipart и возвращает смету. В UI также нет DOCX/TXT среди допустимых расширений.

Исправление: FormData с file, корректный timeout и ошибки, matched/unmatched строки, неизвестное количество и неполная смета.

Места: main frontend/src/main.js:390; [новая ветка: assistantReply](https://github.com/BAITC-Hacks/hack-80299a21-nexis/blob/b499414/frontend/src/main.js#L738).

### 3. P1 — новая frontend-ветка показывает локальную корзину вместо серверной

В b499414 connectBackend получает серверную корзину, но при наличии localStorage отдаёт приоритет локальным данным. Кнопки +/- и удаления меняют только JavaScript/localStorage. Кнопка оформления очищает локальную корзину и показывает сообщение о тестовом заказе; backend ничего не меняет.

Это не относится к старому drawer, отсутствующему в main, но блокирует готовность новой frontend-ветки к объединению.

Исправление: серверная корзина — источник состояния при подключённом API; отдельное хранение синтетического демо-режима. Для изменения/удаления нужны согласованные защищённые endpoint'ы либо временное отключение этих кнопок в серверном режиме. Оформление сейчас должно открывать актуальный cart_url и объяснять режим demo.

Места: [приоритет localStorage](https://github.com/BAITC-Hacks/hack-80299a21-nexis/blob/b499414/frontend/src/main.js#L494), [количество](https://github.com/BAITC-Hacks/hack-80299a21-nexis/blob/b499414/frontend/src/main.js#L441), [оформление](https://github.com/BAITC-Hacks/hack-80299a21-nexis/blob/b499414/frontend/src/main.js#L1033).

### 4. P1 — kz/en в новой ветке не соответствуют API

Backend поддерживает ru и kk. Новая версия UI отправляет language без преобразования: ru/kz/en. Проверено: kz и en дают 422, после чего UI показывает синтетический ответ. В main язык пока фиксирован ru и этой конкретной ошибки нет.

Исправление: kz → kk; для английского согласовать поддержку backend или явно оставить английским только интерфейс, выбрав поддерживаемый язык консультации.

Место: [payload чата](https://github.com/BAITC-Hacks/hack-80299a21-nexis/blob/b499414/frontend/src/main.js#L765).

### 5. P1 — неизвестный остаток превращается в отсутствие товара

normaliseProduct в обеих версиях преобразует quantity=null в 0 и теряет stock_verified, price_verified, last_checked_at и data_quality_warnings. В результате пользователь видит «нет в наличии» вместо «остаток не проверен» и не получает предупреждение о конфликте характеристик.

Исправление: сохранить null и metadata, различать неизвестное/нулевое/положительное наличие. Не разрешать добавление при непроверенных цене или остатке.

Места: main frontend/src/main.js:229; [новая ветка: нормализация](https://github.com/BAITC-Hacks/hack-80299a21-nexis/blob/b499414/frontend/src/main.js#L564).

### 6. P2 — характеристики отображаются как [object Object]

Backend specifications имеет форму [{name,value}], а UI передаёт каждый объект в escapeHtml как строку. Обе версии требуют преобразования в «name: value». Сертификат должен иметь нейтральное название документа: наличие API-ссылки не доказывает конкретный ГОСТ.

Места: main frontend/src/main.js:295; [рендер новой ветки](https://github.com/BAITC-Hacks/hack-80299a21-nexis/blob/b499414/frontend/src/main.js#L631).

### 7. P1 — подтверждение в чате блокируется до backend

isCartIntent перехватывает «добавь», «корзина» и другие слова и выдаёт локальное сообщение. Даже если сервер вернёт cart_updated=true, UI заменяет успешный ответ сообщением об ограничении. Содержательная часть server answer и cart_url теряются.

Исправление: отправлять текст в backend, где уже проверяется привязанное к предложению согласие. Отображать server answer, pending_offer, актуальное состояние корзины и отдельную кликабельную ссылку. Сейчас Markdown-ссылки в ответе экранируются как обычный текст.

Места: main frontend/src/main.js:402/421; [новая ветка](https://github.com/BAITC-Hacks/hack-80299a21-nexis/blob/b499414/frontend/src/main.js#L750).

### 8. P2 — ошибки реального API переводятся в синтетическую консультацию

При ошибке или пятисекундном таймауте чат автоматически использует demoReply. Демо-ответ помечен, но скрывает ошибки интеграции, включая 422 языка. Время tool loop/поиска иногда может превышать timeout UI.

Исправление: показывать отказ API с повтором; запуск синтетического демо делать явным режимом. Согласовать timeout. Синтетические карточки не отправлять в живой API корзины. Повторно проверять подключение после восстановления backend.

### 9. P2 — неподтверждённые условия доставки в новой корзине

b499414 всегда рисует бесплатную доставку по РК от 50 000 ₸, в том числе при подключённом backend. В backend это условие не подтверждено и не возвращается. Демонстрационный сертификат и текст «100% совместимость по ГОСТ» также не являются подтверждением для настоящего товара.

Исправление: получать условия из /purchase-terms и показывать источники; синтетические условия держать только внутри явно выбранного демонстрационного сценария. Не применять их к серверной корзине.

Место: [расчёт порога](https://github.com/BAITC-Hacks/hack-80299a21-nexis/blob/b499414/frontend/src/main.js#L416).

## Что совместимо

- GET /health, /cart и ru-чат используют существующие маршруты.
- Формат ekt_web_<UUIDv4> принимается backend. Резервный timestamp-идентификатор при отсутствии crypto.randomUUID не принимается; предпочтителен POST /session.
- Обёртки sources, reasoning_steps и массив cart в успешном add существуют; проблемы относятся к содержимому/обработке и старому запросу записи.
- CORS разрешает localhost:3000 и localhost:5173.
- Серверные ограничения защищают корзину даже при несовместимом UI.
