# Проверка совместимости backend и frontend

Обновлено 23 сентября 2026. Контракт API v2.1. Исходный frontend напарника: 4b5a172c02e12a8c0317a6feef9a8c9437174634; исправленная реализация подготовлена на его основе. На момент обновления проверяется frontend ea59277.

## История проверки

Первый аудит сравнивал backend 8c99716 с frontend ca7299a и b499414. Тогда было найдено девять расхождений, а по указанию пользователя в main отправили только backend. На том этапе прошли 47 backend-тестов и сборки frontend, но добавление получало 422, языки kz/en не принимались, загрузка и серверная корзина не были соединены с UI.

Повторная проверка 4b5a172 показала, что оформление, TypeScript и маскот обновлены, но старые запросы API сохранены. Дополнительно выявлено, что быстрые вопросы всегда обходили API и что синтетические товары использовали настоящие ID.

Новая задача разрешила совместную доработку backend и frontend. Ниже — статус реализации. «Исправлено в коде» не означает завершения всей браузерной приёмки.

## Исходные расхождения и результат

| № | Ранее | Текущее решение | Статус |
| --- | --- | --- | --- |
| 1 | /cart/add принимал старый frontend payload без подтверждения | /cart/offer → отдельный диалог → /cart/add с confirmed и offer_token | Исправлено в коде; backend-проверки прошли |
| 2 | Вложения не отправлялись, DOCX/TXT отсутствовали в выборе | Настоящая multipart-загрузка всех поддерживаемых форматов и отображение полной сметы | Исправлено в коде; transport/parser проверки прошли |
| 3 | localStorage перекрывал серверную корзину; +/-/удаление были локальными | Серверный snapshot; отдельные change-offer/change с подтверждением | Исправлено в коде; backend-проверки прошли |
| 4 | kz/en давали 422 | KZ → kk, RU → ru; EN-интерфейс использует ru и показывает пояснение | Исправлено; unit-проверка преобразования прошла |
| 5 | Неизвестные остатки превращались в 0 | Сохранены null, verified, предупреждения и время; запись при непроверенных данных недоступна | Исправлено; unit-проверки прошли |
| 6 | Свойства были [object Object], документы назывались ГОСТ без основания | name:value, фактические ссылки на документы, нейтральные названия | Исправлено; unit-проверки нормализации прошли |

## Дополнительные улучшения

- Сессия создаётся сервером. При 401 обновляется; POST не повторяется автоматически.
- Предложение изменения связано с исходным количеством и видом операции. Повтор, конкурентное изменение или новая цена требуют нового подтверждения.
- Если запись могла пройти до таймаута, UI перечитывает корзину.
- Контекст выбранного товара, количества, города и бюджета поддерживает короткие уточнения; RAM, 30 минут, максимум 1024 сессии.
- Приветствие и широкий запрос получают помощь/уточнение. Поиск нормализует обозначения, а запрос более дешёвого варианта проверяет параметры и остаток.
- Docker включает OCR и согласует nginx, API, CORS и ссылки корзины. Native launcher запускает оба dev-сервера.

Backend-тесты используют синтетический транспорт и временные базы. Реальное OCR проверено на читаемом искусственном изображении; это не оценка качества на всех фотографиях. Сборка и unit-тесты не заменяют браузерную приёмку.

Во время браузерной проверки обнаружен Illegal invocation при передаче native fetch без привязки к window. Исправлен вызов транспорта, добавлена регрессионная unit-проверка; проверка вошла в итоговый набор из 21 frontend-теста.

## Итог сквозной проверки

Проверено в Chromium на собранном Docker-стеке:

- Серверная сессия, настоящий quick prompt, карточка 515291 со свойствами, остатком и предупреждением 160/250 А.
- Отмена предложения оставляет корзину пустой; отдельное подтверждение добавляет товар.
- Подтверждённое изменение 1 → 2 и удаление работают через сервер; ссылка показывает актуальные позиции и сумму.
- Текст «Да, добавь» подтверждает предложение на 2 штуки; повтор не добавляет товар снова.
- После перезагрузки страницы серверная корзина восстанавливается; тестовые позиции затем удалены.
- Уточнение «А в Алматы?» сохраняет выбранный товар и показывает остаток города.
- KZ отправляет поддерживаемый язык и получает казахский ответ; EN явно сообщает о русской консультации.
- TXT и PDF проходят путь выбор файла → multipart → найденный товар с количеством 2 → частичная смета → одна неизвестная строка. Корзина от загрузки не меняется.

Найденные при проверке ошибки исправлены: native fetch receiver, количество карточки относительно pending_offer, TXT с разделителем `;`/табуляцией, кириллица старого PDF-примера. Добавлены регрессионные тесты. Примеры: [PDF](sample_specification.pdf), [TXT](sample_specification.txt); генератор — backend/scripts/create_sample_spec.py.

Изоляция сессий, 401, таймауты, 429, изменившиеся цена/остаток, конкурентные подтверждения и nullable поля дополнительно проверяются автотестами. Они не заявляются как отдельные ручные браузерные прогоны. Desktop осмотрен; мобильная вёрстка сохранена, но инструментальный viewport не применил размер 390×844 — проверка на настоящем телефоне остаётся отдельным пунктом.

## Ограничения, не являющиеся расхождением UI/API

- Корзина NEXIS демонстрационная; GET API партнёра не предоставляет запись/заказ/резерв/CRM.
- OpenAI API key в проверенном окружении отсутствует. Работа с настоящей моделью остаётся отдельной проверкой.
- Каталог ограничен выборкой страниц; полного индекса нет.
- OCR в Docker доступен; нативный Windows требует отдельной установки.
- Количество целочисленное; дробный метраж не поддержан.
- EN — язык интерфейса, консультация пока RU. Казахские ответы используют базовые шаблоны.
- Производительность под нагрузкой и публикация на ekt.kz не проверены.
