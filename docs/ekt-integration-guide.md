# Интеграция ChipAI и backend

Реализованный контракт v2.1: [api-contract.md](api-contract.md). Текущий frontend использует серверные сессии, корзину и загрузку файлов. Размещение на самом ekt.kz требует согласования с партнёром.

## Адреса и запуск

| Режим | Frontend | API | Ссылки корзины |
| --- | --- | --- | --- |
| Docker Compose | http://localhost:5173 | /api через nginx; Swagger на localhost:8000/docs | localhost:5173/cart/... через nginx |
| Native dev.py | http://localhost:5173 | http://localhost:8000/api | localhost:8000/cart/... |

В Docker VITE_API_BASE_URL=/api задаётся на этапе сборки. Нативный launcher передаёт фактический API-порт в Vite и CORS. Для самостоятельного frontend можно задать VITE_API_BASE_URL в frontend/.env.local. Любая VITE_ переменная публична: секреты EKT/OpenAI туда не помещаются.

Для Docker публичные ссылки задаются NEXIS_PUBLIC_URL; Compose преобразует его в BACKEND_PUBLIC_URL. Для отдельного backend используйте BACKEND_PUBLIC_URL непосредственно. Существующий .env не перезаписывается.

## Сессии и ошибки

ApiClient создаёт сессию через POST /api/session и сохраняет её идентификатор в localStorage, либо в памяти вкладки при недоступном хранилище. Общий promise предотвращает несколько одновременных созданий. Все запросы передают X-Session-Id; chat JSON также содержит session_id.

При 401 создаётся новая сессия и сбрасываются локальные предложения/корзина. GET можно повторить один раз. POST, включая текстовое подтверждение, автоматически не повторяется: пользователь получает сообщение и выбирает товар снова.

| Ситуация | Поведение UI |
| --- | --- |
| Нет соединения / таймаут | Понятная ошибка; никаких синтетических карточек |
| Неопределённый результат записи | Перечитать корзину, не повторять подтверждение |
| 409: предложение/цена/корзина изменились | Убрать старое предложение, запросить новое и получить новое согласие |
| 413/415/422 | Показать ошибку размера, формата, содержимого или параметров |
| 429 | Показать Retry-After, оставить повтор пользователю |
| 503 | Сообщить недоступность каталога/OCR |

Таймаут чата — 60 секунд, загрузки — 180 секунд. Это верхние границы ожидания UI, а не обещанная скорость ответа. Сервер ограничивает работу инструментов и документов отдельно.

## Чат и карточки

POST /api/agent/chat получает message, history и language. UI отправляет не более 10 предыдущих сообщений. И быстрые вопросы, и свободный текст идут через этот endpoint.

Ответ отображается из answer, sources, knowledge_sources, reasoning_steps, warnings и pending_offer. Текстовые ссылки экранируются и допускают безопасные HTTP(S) URL. Шаги приходят вместе с ответом; во время ожидания UI показывает неопределённую обработку.

Для карточки:

- price/quantity с null или verified:false остаются неизвестными; кнопка добавления недоступна;
- specifications — массив {name,value}, а не готовый текст;
- data_quality_warnings и last_checked_at видны клиенту;
- certificate_url — ссылка на полученный документ, без утверждения о конкретном ГОСТ;
- stores и analogs используются из ответа; имена настоящих товаров не заменяются синтетическими названиями.

RU → ru, KZ → kk. EN → ru для консультации; английский интерфейс показывает «Replies in Russian».

## Полный цикл корзины

Добавление:

1. Покупатель выбирает количество.
2. UI запрашивает POST /api/cart/offer с {product_id,quantity}.
3. Открывается отдельный диалог с серверными товаром, артикулом, ценой, количеством и предупреждениями.
4. Только кнопка подтверждения отправляет POST /api/cart/add с {product_id,quantity,confirmed:true,offer_token}.
5. UI показывает серверный ответ, обновляет позиции и ссылку на сохранённую корзину.

Изменение и удаление используют POST /api/cart/change-offer и POST /api/cart/change. quantity здесь — новое общее количество; 0 означает удаление. Показано предыдущее и новое количество. Отмена диалога ничего не меняет.

Текстовое «Да, добавь» отправляется в агент. Действующее pending_offer можно подтвердить текстом или через UI; backend проверяет, что это согласие на конкретное предложение. При cart_updated:true интерфейс перечитывает корзину. Другой товар, количество, устаревший токен и отсутствие согласия не разрешают запись.

Панель корзины читает серверное состояние; увеличение, уменьшение и удаление не сохраняются только в браузере. Открытие ссылки не очищает позиции. После успешной записи отображается фактический ответ backend, включая актуальные значения товара и количества.

## Спецификация

Каждый выбранный файл отправляется FormData-полем file в POST /api/agent/upload-spec. Content-Type и multipart boundary устанавливает браузер. Разрешены PDF, TXT, DOCX, XLSX, XLS, JPEG, PNG и WEBP до 15 МиБ.

UI показывает:

- matched_items с количеством, ценой, наличием, суммой и карточкой;
- unknown quantity и quantity_warning без подстановки 1;
- unmatched_items с причиной и кандидатами;
- ignored_lines, общие предупреждения и признак неполной сметы;
- предложенный аналог там, где он вернулся из backend.

Загрузка не создаёт предложение корзины автоматически и не добавляет позиции. Для каждого выбранного товара действует обычный цикл подтверждения. При отсутствии OCR фото/скан получает явную ошибку; в Docker движок включён.

## Что означает ссылка на корзину

cart_url/checkout_url открывает /cart/<read_token>. Эта страница показывает актуальное состояние SQLite-корзины; токен даёт только чтение и действует 10 минут. UI при открытии панели/страницы запрашивает актуальную ссылку.

partner_cart_url ведёт на отдельную корзину ekt.kz. Содержимое туда не передаётся. Для реального оформления нужны официальные методы корзины, авторизация покупателя, идемпотентность, резервирование и URL возврата. Платёжные данные приложение не принимает.

POST /api/manager/escalate возвращает manual_handoff_required и официальные контакты. Комментарий не отправляется и заявка не создаётся; для автоматической передачи нужен CRM API.

## Приёмка и размещение

Backend: 75 тестов прошли на Windows и в Linux-контейнере. Frontend: 20 unit-тестов, typecheck и build прошли. Реальный OCR проверен на сгенерированном изображении. Полный браузерный сценарий пока проходит отдельную приёмку: [статус аудита](frontend-backend-audit.md).

Для публикации настройте HTTPS, публичный URL, точные CORS origins, хранилище SQLite и лимиты на reverse proxy. Перенос на сайт партнёра пока не выполнен. Контекст выбора, кеш и лимитер локальны процессу; работа нескольких воркеров и нагрузочный SLA требуют отдельного решения.
