# Backend NEXIS — API v3

FastAPI, клиент ekt.kz, агент с маршрутизацией и контекстом, поиск знаний на RU/KK/EN, обработка документов и SQLite-корзина. Все команды ниже выполняются из корня репозитория.

## Запуск

Для общего запуска с frontend и OCR используйте [Docker-инструкцию](../docs/docker-setup.md):

~~~powershell
if (!(Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
# Заполните EKT_API_USER и EKT_API_PASS, сохранив существующие настройки.
docker compose up --build -d
~~~

Для разработки на Windows: Python 3.14, Node.js 24.

~~~powershell
python backend/scripts/dev.py --install
# Последующие запуски:
python backend/scripts/dev.py
~~~

Флаг --install подготавливает .venv, устанавливает Python/npm зависимости и запускает оба сервера. Ctrl+C завершает дочерние процессы. Для отдельных портов доступны --api-port и --ui-port.

Backend отдельно после установки зависимостей:

~~~powershell
.\.venv\Scripts\python.exe backend/main.py
~~~

На Linux путь Python — .venv/bin/python. .env загружается из корня репозитория независимо от текущего каталога.

- Swagger: http://localhost:8000/docs
- Состояние: http://localhost:8000/api/health
- Интеграции: http://localhost:8000/api/integrations

Нативный сервер слушает 127.0.0.1; Docker задаёт HOST=0.0.0.0 внутри контейнера и публикует порт на localhost. Локальные SQLite создаются в database/nexis.sqlite3, database/knowledge.sqlite3 и database/catalog.sqlite3. В Docker они находятся в /data на постоянном volume. Контекст диалога остаётся в RAM и в эти базы не переносится.

## Сессия и консультация

Сессия — случайный секретный идентификатор гостевой корзины, а не учётная запись покупателя. Получите его через /api/session, передавайте в X-Session-Id; для чата он также требуется в JSON.

~~~powershell
$api = 'http://localhost:8000'
$session = Invoke-RestMethod -Method Post "$api/api/session"
$headers = @{ 'X-Session-Id' = $session.session_id }
$body = @{
  session_id=$session.session_id
  message='515291'
  history=@()
  language='ru'
} | ConvertTo-Json
$reply = Invoke-RestMethod -Method Post "$api/api/agent/chat" -Headers $headers -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
$reply.answer
$reply.sources
~~~

Языки API: ru, kk и en. Чат принимает language в JSON. Остальные API поддерживают параметр ?language=en или заголовок X-Language: en; приоритет у query-параметра. Ответы содержат answer_language, HTTP-заголовок Content-Language сообщает язык. Интерфейс KZ отправляет kk, EN — en. Локализуются ошибки, подписи характеристик, сметы, подтверждения, HTML и CSV корзины; названия, артикулы и исходные значения из каталога сохраняются.

AgentService различает поиск товара, техническое объяснение, условия покупки и уточнение. Он поддерживает «а в Алматы», «нужно 5 шт.», «подешевле», выбор первого/второго/третьего варианта и сравнение последних кандидатов. RAM-контекст содержит product_id, quantity, city, budget, family, language, candidate_ids, selected_ids, constraints, pending_clarification, topic и revision. Срок — 30 минут с последнего обновления, максимум 1024 сессии и до 10 ID в списке кандидатов/выбора. Сообщения и файлы в этот контекст не записываются; после перезапуска он теряется.

При наличии OPENAI_API_KEY модель OPENAI_MODEL (по умолчанию gpt-4o-mini) выбирает пять инструментов чтения. При отсутствии/ошибке модели используются программные правила с тем же каталогом и лексической базой знаний. Цикл ограничен тремя итерациями и шестью инструментами. Общий бюджет агентского запроса задаётся AGENT_TIMEOUT_SECONDS: по умолчанию 10 секунд, диапазон 1–30; это ограничение обработки, а не гарантия SLA всего HTTP-запроса.

Цена, наличие и спецификации выводятся из карточек. Для пояснений composer принимает подтверждённые выдержки из найденного корпуса; произвольный модельный ответ не становится источником фактов. Уже полученные результаты инструментов сохраняются при последующей ошибке планировщика. У модели нет инструмента записи корзины.

Дополнительные поля ответа: request_id, answer_language, clarification, warning_codes, локализованные warnings и diagnostics с mode, elapsed_ms, retrieval_mode, fallback_reason и tool_calls. reasoning_steps содержит коды/статусы выполненных действий; SSE не реализован. Health показывает конфигурацию и состояние индексов, а не гарантирует доступность ekt.kz/OpenAI. В текущем окружении ключ отсутствует; реальные вызовы модели и embeddings не выполнялись.

## База знаний и поиск

database/knowledge/articles.json содержит 53 материала на RU/KK/EN, текущий индекс — 159 фрагментов. Это условия покупки, технические пояснения, вопросы для подбора и описание прототипа. Каждый материал имеет источник, версию, статус проверки и языковые варианты. Метаданные ответа включают chunk_id, source_id, content_hash, verified_at, retrieval_mode и причину перехода на лексический поиск, когда она есть.

Индекс SQLite строится автоматически при первом обращении. Явное построение без сети:

~~~powershell
.\.venv\Scripts\python.exe backend/scripts/index_knowledge.py
~~~

Лексическое ранжирование учитывает слова, заголовки и ключевые выражения всех переводов; пользователю выдаётся выбранный язык. Гибридный поиск объединяет лексические ранги с косинусным сходством embeddings. Отдельный векторный сервис не требуется.

Embeddings включаются явно и требуют платных запросов OpenAI:

~~~powershell
# Нужен OPENAI_API_KEY в .env; команда создаёт векторы изменённых фрагментов.
.\.venv\Scripts\python.exe backend/scripts/index_knowledge.py --embeddings
~~~

Для запросов с векторами задайте NEXIS_EMBEDDINGS_ENABLED=true и перезапустите backend. NEXIS_EMBEDDING_MODEL по умолчанию text-embedding-3-small; при смене модели перестройте векторы. Без ключа, готового индекса или при ошибке доступен лексический поиск. Путь задаёт NEXIS_KNOWLEDGE_DB_PATH. Изменение содержания вызывает обновление индекса, удалённые материалы исключаются, старые несовместимые векторы не используются.

Источники корпуса — страницы ekt.kz и материалы производителей ABB/Schneider Electric. Статусы отделяют просмотренный источник от условий, требующих менеджера, и редакционной инженерной памятки. Казахские переводы требуют вычитки носителем. Подробнее: [происхождение и правила корпуса](../database/knowledge/README.md).

## Постоянный индекс каталога

~~~powershell
.\.venv\Scripts\python.exe backend/scripts/import_catalog.py --max-pages 100
# Продолжить с сохранённой страницы:
.\.venv\Scripts\python.exe backend/scripts/import_catalog.py --max-pages 100
# Начать новую выгрузку:
.\.venv\Scripts\python.exe backend/scripts/import_catalog.py --restart --max-pages 100
~~~

Нужны EKT_API_USER/EKT_API_PASS. CLI делает GET-запросы, ограничивает число страниц за запуск, повторяет HTTP 429 с ограниченным ожиданием и сохраняет checkpoint в NEXIS_CATALOG_DB_PATH. Повторяющаяся страница останавливает импорт. Только успешная пустая страница завершает снимок и позволяет удалить старые ID, не встретившиеся в новом поколении.

Текущий локальный импорт: 11 страниц, 220 товаров, next_page:12, complete_catalog:false. Это данные конкретного запуска, не содержимое Git или Docker-образа. Поиск использует индекс и уже загруженные страницы. Когда индекс пуст, автоматически загружается начальная выборка EKT_CATALOG_PAGES. Индекс нужен для нахождения ID: цены, остатки и склады исключаются из поисковых записей, а карточка запрашивается из API перед ответом. Coverage в /api/health показывает фактический объём, checkpoint и состояние импорта.

## Добавление после подтверждения

Первый запрос проверяет данные и возвращает предложение; корзина не меняется:

~~~powershell
$selection = @{ product_id=515291; quantity=1 } | ConvertTo-Json
$offer = Invoke-RestMethod -Method Post "$api/api/cart/offer" -Headers $headers -ContentType 'application/json' -Body $selection
$offer
~~~

Покажите покупателю товар, артикул, количество, цену и предупреждения. Только после его согласия:

~~~powershell
$confirmation = @{
  product_id=$offer.product_id
  quantity=$offer.quantity
  offer_token=$offer.offer_token
  confirmed=$true
} | ConvertTo-Json
$result = Invoke-RestMethod -Method Post "$api/api/cart/add" -Headers $headers -ContentType 'application/json' -Body $confirmation
$result.answer
$result.cart_url
~~~

Токен связан с сессией, ID, количеством, ценой и операцией. При подтверждении сервер снова читает карточку, проверяет совокупное количество и потребляет токен в транзакции. Повтор, другая сессия или изменившаяся цена отклоняются.

Текст «Да, добавь», «Иә, қос» или «Yes, add» разрешает добавление только для действующего chat-предложения. История, цитата, отрицание и вопрос не выдают согласие. Изменение количества в диалоге требует нового предложения. RAM-контекст и результаты модели не заменяют серверный токен согласия.

## Изменение и удаление

| Действие | Подготовка | Подтверждение |
| --- | --- | --- |
| Добавить количество к имеющемуся | POST /api/cart/offer | POST /api/cart/add |
| Установить новое общее количество | POST /api/cart/change-offer | POST /api/cart/change |
| Удалить позицию | change-offer с quantity:0 | change с quantity:0 |

Обе пары принимают product_id и quantity; запрос подтверждения дополнительно принимает confirmed:true и offer_token. Для изменения quantity — итоговое количество, не приращение. Предложение содержит operation:set_quantity и previous_quantity.

Сервер отклоняет устаревшее предложение, если исходная корзина уже изменилась. Для положительного количества снова проверяются цена и остаток. Удаление локальной позиции разрешено при недоступном каталоге, но также требует подтверждения. Токены разных операций невзаимозаменяемы.

GET /api/cart возвращает текущее состояние и checkout_url. GET /api/cart/export формирует CSV. Ссылка /cart/<read_token> показывает актуальную сохранённую корзину и действует 10 минут. Просмотр не очищает корзину и не создаёт заказ.

## Документы и OCR

~~~powershell
curl.exe -H "X-Language: en" -F "file=@C:\path\specification.pdf" http://localhost:8000/api/agent/upload-spec
~~~

Поддерживаются PDF/TXT/DOCX/XLSX/XLS/JPEG/PNG/WEBP. Ограничения: файл 15 МиБ, multipart 16 МиБ, 250 товарных строк, 100 тысяч извлечённых символов, PDF 50 страниц и до 10 сканов, изображение до 16 Мп. Формат проверяется по содержимому; архивы ограничены размером распаковки.

Результат содержит matched_items, unmatched_items, ignored_lines, предупреждения и estimate_complete. Неизвестные количества остаются null. Неполная смета показывает известную часть суммы; загрузка не изменяет корзину. Статусы и сообщения локализуются, status_code сохраняет машинный код, answer_language сообщает язык.

Docker содержит Tesseract и eng/rus/kaz. Нативный запуск требует отдельной установки движка и языковых данных, затем настройки TESSERACT_CMD или PATH. /api/health проверяет executable; doctor дополнительно проверяет языки и реальное распознавание:

~~~powershell
.\.venv\Scripts\python.exe backend/scripts/doctor.py
docker compose run --rm --no-deps backend python backend/scripts/doctor.py --require-ocr --ocr-smoke
~~~

Без движка фото/скан возвращает ocr_unavailable. Качество зависит от читаемости маркировки; распознавание товара только по внешнему виду не реализовано. Старый .doc нужно сохранить как .docx.

## Данные, защита и эксплуатация

- Credentials ekt.kz/OpenAI остаются на backend. Партнёрские запросы — только GET по HTTPS с Basic Auth.
- Кеш страниц — 300 секунд, деталей — 30 секунд по умолчанию. Изменения корзины с положительным количеством проверяют свежие данные.
- EKT_CATALOG_PAGES управляет оперативной выборкой (по умолчанию 4, максимум 50); постоянный индекс расширяется отдельным CLI. Прямой числовой ID доступен за пределами выборки. Coverage описывает фактическое покрытие, а не наличие полного каталога по умолчанию.
- SQLite хранит хеши сессий, позиции, предложения и хеши ссылок чтения. Сессия по умолчанию 24 часа, предложение/ссылка — 10 минут. Просроченные данные очищаются при запросах; фоновой политики удаления нет.
- Полная история не сохраняется в БД. В браузере для API ограничивается последними 10 сообщениями. При включённой модели ограниченная история и результаты инструментов передаются OpenAI.
- Файлы не сохраняются приложением и не передаются модели; multipart может использовать временный файл, который закрывается после обработки.
- Явные платёжные реквизиты отклоняются. Гостевая сессия и ссылки корзины дают доступ владельцу токена, поэтому их нельзя публиковать.
- CORS разрешает localhost/127.0.0.1 на 3000/5173; дополнительные адреса задаются CORS_ORIGINS.
- Контекст диалога, оперативный кеш и rate limiter локальны одному процессу; индексы знаний/каталога сохраняются в SQLite. Для нескольких воркеров нужны общее состояние/лимиты и проверка нагрузки. Внешний reverse proxy должен корректно ограничивать запросы; произвольному X-Forwarded-For backend не доверяет.

Корзина не резервирует остатки ekt.kz и не передаёт заказ партнёру. CRM отвечает ссылкой на контакты без фиктивной заявки. Для настоящего оформления и эскалации нужны официальные контракты партнёра.

## Проверки

~~~powershell
.\.venv\Scripts\python.exe -m unittest discover -s backend/tests -p "test_*.py" -v
.\.venv\Scripts\python.exe -m backend.evals.run
.\.venv\Scripts\python.exe backend/scripts/smoke_live.py
~~~

Исходная версия до v3 прошла 81 backend-тест на Windows/Python 3.14.6 и Docker/Linux/Python 3.14.7, OCR на сгенерированном изображении и HTTP-запуск. Для v3 отдельно прошли 16 проверок локализации и 40 целевых проверок retrieval; итог полного набора фиксируется в [журнале v3](../docs/agent-v3-implementation.md). Пересекающиеся наборы не суммируются.

Unit-тесты используют синтетический транспорт и временные SQLite. backend.evals содержит 72 офлайн-сценария (24 задачи × 3 языка): это набор разработки, не независимая оценка LLM. Runner отключает внешнюю модель и embeddings, не меняя .env. [Подробнее об оценке](evals/README.md).

Live smoke отдельно читает настоящий API с .env и проверяет временную локальную корзину; записей у партнёра нет. Работа настоящей модели, платный гибридный поиск, нагрузка и браузерная приёмка v3 оцениваются отдельно.
